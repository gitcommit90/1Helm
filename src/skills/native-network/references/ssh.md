# SSH and SFTP

1. Call `native_network` with operation `status`. Check `available`, `client`, `permission`, key, session and Tailscale state. Available only means this deployment supports the native operations. The client separately reports verified_ready, sleeping, error or unverified. Sleeping/unverified is not proof of an active client or connection; a new approved open must verify the real transport. Do not infer readiness from installed shell software or a previous message.
2. Settings → Permissions → Direct network protocols → Outbound SSH offers Deny, Ask each time, and Allow trusted servers. Missing settings, including existing accounts, remain Deny. Deny opens no native SSH session. Ask requires human approval for every new session. Allow trusted servers permits reconnecting only after the person explicitly chooses to remember that exact server in a native approval card; selecting the mode alone trusts nothing, and old one-time approvals are never promoted. HTTP Always Approve and spending permissions are independent.
3. Call `native_network` operation `key` to provision/inspect this channel computer's persistent Ed25519 public key and SHA256 fingerprint. The person can copy it in Settings → Connected accounts → Computer connections. Install that one public-key line in the intended server account's `~/.ssh/authorized_keys`. Never request their private key or password. A server address and username can be shared normally.
4. For a public server, call `ssh_connect` with `host`, `username`, `route: public`, and optional `port` (default 22, explicit custom ports supported). For a private Tailscale server, first complete actual native enrollment, then use `route: tailnet`. There is no public fallback for that route. Do not pass a URL, ProxyCommand, or forwarding flags. A Cloudflare Tunnel hostname may require a separate tunnel-aware transport; this feature does not supply one.
5. `ssh_connect` returns connected with a new session_id directly when an explicitly remembered target still matches in Allow trusted servers mode. Otherwise awaiting_approval means a native card is waiting. End the turn with a short status. Do not retry in a loop, invent your own approval, or keep the computer running. Waiting state survives ordinary Worker restarts. Each request is bound to the account, channel, initiating task/run, pinned target/address, port, username and route, and expires after 10 minutes. Remembered authorization also pins the verified server fingerprint, this computer's key generation, and any tailnet peer/route/enrollment generation. DNS/address or server identity changes do not inherit remembered approval.
6. The first approved handshake may return state host_key_confirmation_required. No remote authentication has occurred; that connection closes. A second human card shows the server fingerprint. The person compares it through a trusted channel. A changed fingerprint must be explicitly resolved; never silently accept a replacement. The second approval authorizes a fresh connection with the specified fingerprint. An explicit remember choice carries through this confirmation, but is saved only after a verified authenticated connection succeeds. Approve once never creates remembered authorization. After a remembered server changes its key, the person must explicitly choose whether to remember the replacement; a one-time replacement approval does not rewrite remembered trust.
7. After human approval the task resumes with a managed session_id; an automatic trusted connection returns that ID directly to the current tool call. Call `ssh_session` with `operation: exec`, session_id, and `command`; or `operation: sftp` with sftp_operation (`list`, `read`, `write`, `mkdir`, `remove`, `rename`, `stat`), `path`, optional `destination`, and `data` for writing. Set `encoding` to utf8 (default) or base64 for binary files. Each transfer call is limited to 1 MiB; larger files use multiple calls with byte `offset` and read `length`. Read results include bytes, next_offset and eof. Write without offset truncates the file; explicit offset preserves other bytes unless `truncate` is true. Keep output bounded and check each chunk result. These operations share the same authenticated transport. Sessions close after 5 idle minutes and have a 30-minute hard lifetime. Reconnect with `ssh_connect`; Ask requires another approval, while matching remembered servers reconnect automatically in Allow trusted servers. Each connection still receives a fresh, task-bound session. Check actual operation results before saying a command or transfer succeeded.
8. Close using `ssh_session` operation `close` and the session ID, or use Terminate in Computer connections. Task Stop, deletion, and changing SSH to Deny terminate managed sessions and cancel waiting requests. Lost, expired or rejected sessions need a fresh request. Settings may report that a termination still needs acknowledgment; do not claim it is complete until confirmed.

No SSH agent forwarding, local/remote/dynamic port forwarding, arbitrary proxy command or background ControlPersist is exposed. These controls gate direct managed SSH sessions; remote commands still have the remote account's permissions and network access. Existing HTTP/HTTPS Sentinel rules remain a separate policy. Arbitrary data encoded inside permitted HTTPS is not a claim of command-level or general information-flow enforcement.

Computer connections lists remembered servers with an explicit revoke control. Revocation removes automatic authorization, cancels matching pending requests, and closes that server's managed sessions; retry if termination is still pending. Ask/Deny preserve the list but disable automatic authorization; switching back to Allow trusted servers re-enables the remaining exact matches. Deny also terminates sessions. These SSH choices do not authorize purchases or override any other app approval.

The private identity is encrypted in platform-owned storage outside downloadable workspace snapshots and model-visible command output. Ordinary sleep/wake retains it and remembered trust; sessions may close and reconnect follows the selected SSH setting. Rotation in Settings closes managed sessions, clears remembered servers and replaces the key. Install the new public key before reconnecting and remove the old public-key line from servers if desired. Explicit Tailscale disconnect clears remembered tailnet servers as well as enrollment; public-server trust is unchanged. Removing a public key from a server blocks future authentication but does not itself disconnect an already authenticated session; use Terminate as well.

Errors: denied → the person chooses Ask each time or Allow trusted servers; awaiting_approval → wait for the native card; expired/rejected/cancelled → obtain a new request only if the person still wants the connection; host-key mismatch → verify with server owner before explicit replacement; unreachable → verify route, port, server firewall and tailnet policy; unavailable → report the platform limitation without claiming readiness.
